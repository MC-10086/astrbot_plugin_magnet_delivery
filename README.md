# AstrBot 磁力下载与回传

版本 **1.0.0**，适用于 AstrBot `>=4.29.4,<5`。**`/magnet` 指令由插件直接处理，无需 Agent 或 LLM。**

支持 QQ OneBot v11 群聊中提交磁力、按聊天查看任务、取消、选择后端，下载完成后生成 ZIP 并调用群文件上传接口。实际 QQ 交付以支持 `upload_group_file` 的协议端（例如 NapCat）为前提。

## 已实现

- WhatsLink 只读预览：名称、类型、大小、文件数量和已有截图；不创建下载任务，也不依赖下载器已配置。
- 支持 Windows 迅雷官方 CLI、qBittorrent Web API、aria2 自动管理和 aria2 JSON-RPC 手动连接。高级 JSON 可保存多个连接，指定其中一个用于新任务。
- 每个群独立设置启用和自动监听。所有新任务统一使用插件配置中选定的下载器。
- 自动压缩、密码保护、自动发送可分别设置，支持全局默认、本群设置及单次任务覆盖；默认自动压缩、不加密、自动发回原群。
- “自动发送成功后删除本地文件”默认开启；整批文件确认发送成功后清理，上传失败时保留。清理失败可单独重试。
- 群聊指令的任务范围为“平台实例 ID + 群号”，不会因同群按人分会话而分裂；群内不能查看或取消其他群、其他实例的任务。登录管理面板后可在任务视图中管理所有群，仍按实例和群聊分组。
- 群内可查看全群任务。普通用户可取消自己的任务，QQ 群主/管理员或 AstrBot 管理员可以管理本群任务。
- 排队、进度、并发限制、下载超时、资源大小及文件数限制、磁盘空间检查。
- SQLite 保存任务；插件重载后恢复下载轮询或重新压缩。后台 ZIP 子进程可被取消，不阻塞消息处理。
- 提供“任务管理”图形视图，自动刷新进度、速度、状态，可筛选机器人及群聊，取消任务并清理文件。
- 取消时先确认下载器任务已移除，再删除该任务的下载目录、ZIP及临时文件；不会接管下载器里的个人任务。失败明确显示，支持重试。
- 上传超时或异常后标为“结果未知”，不自动重发；核对群文件后可显式重发。

## 当前边界

- 仅支持 **QQ OneBot 群聊**；私聊、QQ 官方机器人暂不承诺兼容。
- 仅支持 BT v1 / BTIH 磁力。BT v2-only、种子文件、迅雷链接、普通 HTTP 下载尚未接入。
- ZIP 超过单文件上限时自动分卷，普通 ZIP 和加密 ZIP 均支持。每卷默认 3800 MiB（约 3.98 GB），单任务下载上限默认 8 GiB，两项都可在插件配置中调整。把全部分卷放在同一目录，用支持分卷的压缩软件打开 `.zip.001` 解压。
- 压缩包及分卷保存在下载目录下的 `<任务完整编号>.archives/`。关闭自动清理时，保留已完成任务的下载文件与压缩包。取消任务也会清理该任务的文件。
- 同一后端的相同哈希不并行下载；不同群触发会得到不含其他群信息的拒绝提示。没有跨群共享交付。
- qBittorrent 默认完成后暂停做种并保留任务记录；开启发送后清理会在发送成功后移除该任务和文件。保留任务记录时，同一资源以后再次提交可能被拒绝；请管理员确认后在qB删除旧任务，再提交新任务。
- 停用/卸载插件会停止插件调度和压缩子进程，**外部下载器的任务可能继续运行**；需要停止时先在群内 cancel，或到下载器中停止。重启恢复依赖下载器仍保留任务（aria2 尤其需要配置会话保存）。
- “已交付”表示 OneBot 群文件接口接受了上传请求。启用自动清理时还要求每个文件都有 `file_id` 回执。首次部署请在测试群确认文件可下载和解压。
- 本插件没有加速资源库；下载速度仍取决于资源与网络。

## 安装

1. 使用 AstrBot WebUI 插件页的本地 ZIP 安装功能导入发行 ZIP；或将完整目录放入**实际运行实例**的 `data/plugins/astrbot_plugin_magnet_delivery/`。
2. 依赖只有 `httpx`（写在 requirements.txt）。不要把插件放到桌面程序 exe 旁边，也不要默认安装目录就是运行数据目录。
3. 在 WebUI 插件配置的「下载器」下拉菜单中选择一个已安装的下载器，保存后重载插件。使用迅雷请先完成[迅雷官方 CLI 安装](#迅雷官方-cliwindows)。「未选择」时仍可使用预览。
4. 启动并连接 OneBot 协议端，例如 NapCat。qBittorrent 和手动连接的 aria2 需自行运行。选择 aria2 自动管理时，由插件启动已安装的 `aria2c`。

## 后端配置

### 图形化任务管理

启用插件后，打开 **AstrBot → 插件 → 点击本插件名称进入详情 → 插件行为 → 页面 → tasks → 打开**。插件卡片的“打开视图”快捷按钮可能直接打开第一个paths页面，因此进入任务管理请从详情选择tasks。目录设置仍是单独的paths视图。

左侧“扩展功能”启用“按插件分组”后，展开本插件可看到“任务管理”。悬停其入口并点击图钉即可置顶，以后从侧栏直接进入。

管理页按“机器人实例＋群号”分组显示资源名称、任务编号、下载器、提交者、状态、下载百分比、大小、速度及交付设置；支持机器人、群聊和状态筛选，每3秒刷新，也可手动刷新。默认展示进行中、本机就绪及需要处理的异常；“全部”包含最近100条结束记录。该页面属于已登录AstrBot管理面板的管理员，能够管理所有群的插件任务；群内指令仍遵守原有群范围和提交者权限。

点击 **取消并清理**，在确认框内确认后，插件会：

1. 等待尚在提交中的下载操作结束，终止压缩子进程，防止取消后又创建任务或临时文件。
2. 核验任务归属并移除下载器记录。qB使用删除任务及文件接口并确认任务消失；aria2处理元数据及后续任务，移除结果记录，并刷新已配置的会话文件。
3. 校验绝对路径，只删除该任务编号对应的下载目录（含断点及未完成文件）与压缩临时文件，确认不存在后才标记“已取消并清理”。保留简短的取消状态记录用于确认，不再保留该任务的磁力、文件列表及本机路径字段。

“取消与清理中”表示仍在执行，不能视为已完成。“移除任务失败”时不冒险删除仍可能被写入的文件；“文件清理失败”表示下载器已移除，但文件被占用、目录权限或路径检查阻止清理。修复问题后点击“重试取消”或“重试清理”。重载期间尚未完成的清理会恢复，只有完成文件检查才会显示成功。

上传中的任务不能可靠撤回，按钮会禁用；上传结果未知时请先核对群文件。已发到群里的文件不会因本机取消而自动删除。任务视图和取消接口要求管理面板登录，不接受浏览器传入任意删除路径，刷新响应不包含磁力、下载器凭据或本机路径。

### 下载完成后的处理

在插件配置中展开 **下载完成后的处理**。三个开关分别控制“自动压缩为 ZIP”“为压缩包设置密码”“完成后自动发送到原群”。默认开启压缩和自动发送，关闭密码保护。

开启 **完成后自动发送到原群** 时，才会显示 **自动发送成功后删除本地文件**，新装插件默认勾选，可按需关闭。关闭自动发送后，该选项隐藏且对新任务无效；手动`send`不会触发这项自动清理。

开启后，全部文件上传成功才会移除下载器任务并删除本地下载内容、ZIP、断点和临时文件。发送原文件时会等整个批次完成，保留尚未确认的当前文件及同批次文件。上传失败、超时或结果未知时不删除、不自动重发。成功确认以群文件接口返回成功且包含`file_id`为依据，协议端须支持该响应；旧版或其他协议端未提供回执时，显示结果未知并保留文件。[NapCat上传接口说明](https://napcat.apifox.cn/226658753e0)

任务页会区分“已发送，清理中”“已发送，清理失败”和“已交付并清理”。清理失败后点击“重试清理”，或由任务所有者/本群管理员执行`/magnet cleanup <任务编号>`，仅重试清理，不重新上传。重载后恢复未完成清理；只有已确认发送且提交时选择该选项的任务才能删除文件。旧任务不会因升级或修改全局设置而自动启用清理，群文件不会被删除。

| 自动压缩 | 自动发送 | 结果 |
|---|---|---|
| 开 | 开 | 下载后生成 ZIP，再上传到原群（默认） |
| 开 | 关 | 生成 ZIP 保存在本机，使用 `/magnet send <编号>` 手动发送 |
| 关 | 开 | 将下载的原文件逐个上传到原群，保留原文件名 |
| 关 | 关 | 下载完成后保存在本机，使用 `/magnet send <编号>` 手动发送原文件 |

**压缩方式**默认「系统 ZIP」(`auto`)。普通压缩在 Windows 上调用系统自带 ZIP 接口，其他系统或缺少 Windows PowerShell 时使用插件内置 ZIP。可手动选择「插件内置 ZIP」(`builtin`) 或「7-Zip」(`7zip`)。需要密码保护时，默认模式会调用 7-Zip；插件内置 ZIP 模式只支持普通 ZIP。7-Zip 程序路径通常留空，找不到时可填写 `7z.exe` 的绝对路径。

密码保护需要压缩开启，并使用 7-Zip 创建 AES-256 ZIP；不满足时在入队前拒绝，不会静默生成未加密文件。密码在管理面板敏感字段中配置，使用1至99位英文、数字或符号，不含中文或双引号。该限制来自7-Zip ZIP密码及Windows命令行兼容性；不会自动向群里发送密码，请另行告知接收者。加密 ZIP 仍可看到文件名，解压软件须支持 AES ZIP。插件不将密码明文写入任务记录、临时清单或日志；外部工具的进程参数包含密码，本机有相应权限的进程检查工具仍可读取。等待压缩的加密任务完成前请勿修改密码；检测到密码改变会停止压缩。

群管理员可以单独修改本群新任务的默认行为：

```text
/magnet delivery                 查看本群当前设置
/magnet compress on|off|default  自动压缩；default 恢复全局值
/magnet encrypt on|off|default   密码保护（密码仍在管理面板配置）
/magnet autosend on|off|default  自动发送文件
/magnet autodelete on|off|default  自动发送成功后清理（需先开启autosend）
```

普通用户也可以在单次任务后添加选项，优先于群设置和全局默认：

```text
/magnet add <磁力> [后端] --no-send
/magnet add <磁力> [后端] --no-compress --no-encrypt
/magnet add <磁力> [后端] --compress --encrypt --send
```

三个选项均支持 `--compress/--no-compress`、`--encrypt/--no-encrypt`、`--send/--no-send`。关闭压缩时必须同时关闭已启用的密码保护。设置在入队时固定，更改仅影响新任务；旧版本任务保持自动 ZIP、不加密、自动发送。手动发送和重发仍按平台实例及群号隔离，只有任务提交者或本群管理员能操作。不会在QQ聊天中回显本机目录。

单次任务还可用`--delete-after-send`或`--no-delete-after-send`覆盖发送后的清理选项。显式选择清理时必须同时开启自动发送；只添加`--no-send`会关闭该任务继承的自动清理。

关闭自动发送的任务在 `tasks` 中显示“本机已就绪”。`send` 只发送已就绪任务，`resend` 只处理核对后的失败或结果未知上传。上传前会检查整个批次，每个分卷或原文件都须满足单文件上限。已确认成功的分卷或原文件会在重试时跳过，结果未知的当前文件须先核对群文件。

### 点击浏览选择下载目录

启用插件后打开 **AstrBot → 插件 → 本插件详情 → 页面 → paths（目录设置）→ 打开**。默认只显示一个“统一下载目录”，所有下载器共用；留空使用 `data/plugin_data/astrbot_plugin_magnet_delivery/downloads/`。点击“浏览”选择文件夹，选完点击“保存路径”，然后重载插件。aria2程序路径单独选择。

需要单独存放时，开启 **为当前下载器设置独立目录（可选）**。关闭并保存后，当前下载器恢复使用统一目录。

统一的是下载器的根目录，每个任务仍放在不同的任务编号子目录，取消清理只删除对应任务。升级前使用旧版默认 `downloads/qb/`、`downloads/aria2/` 的任务会在原位置继续处理，使用同一服务地址核验原指纹；不会自动移动旧文件。该兼容不放宽服务地址变更检查，也不接管任意旧路径。

普通配置弹窗仍是AstrBot标准文本字段；交互式目录选择放在插件视图中，不修改AstrBot核心。留空或点击“清空”并保存会恢复自动默认目录。目录设置页只修改路径，不回显或更改账号、密码、密钥和启用开关。

升级后若“浏览”提示“未找到该路由”，请先启用插件，再点击插件卡片的“重载插件”，然后重新打开目录设置页。本机AstrBot 4.29.4在插件停用期间重载时可能保留旧模块缓存，导致新页面已更新但后台接口尚未加载；仍未恢复时可重启AstrBot。

目录选择器显示 **运行 AstrBot 的电脑**上有权限访问的本机文件夹。目录较多时可翻页，也可将资源管理器里复制的绝对路径粘贴到地址栏，点击“前往”。Windows 目录链接会标注，请选择实际目标目录。已有任务运行时，请先完成或取消后再更改后端目录；配置改变会触发现有任务的后端身份保护。

### 最简单：aria2 自动管理（推荐）

1. 在插件配置顶部选择 **aria2（自动管理）**。
2. 在程序路径填写 `aria2c.exe` 的完整路径，例如 `C:/Tools/aria2/aria2c.exe`。填写实际程序文件。若程序已加入 PATH 可留空。
3. 保存并重载插件。

无需手写 aria2.conf、填写端口或密钥，也无需打开或保留命令窗口。下载目录可留空，由插件创建。后台进程仅在本机监听RPC，密钥随机生成。使用 `/magnet backends` 查看状态，管理员可用 `/magnet test aria2` 测试连接；这两个命令不会创建下载任务。

插件只启动和停止自己的子进程，不会关闭其他aria2程序。停用/重载时先保存会话并关闭自建实例，已下载文件保留；重新启用时加载会话并继续轮询可恢复的任务。异常强退或下载器自身丢失任务时不保证恢复全部状态；进程异常退出会在状态中显示，重载可尝试重新启动。

自动生成的配置、连接参数、会话和DHT数据保存在 `data/plugin_data/astrbot_plugin_magnet_delivery/managed_aria2/`，不修改用户现有aria2.conf。生成的端口和密钥会复用，使重载后已有任务仍能关联。不要把此数据目录打包分享，也不要删除其中连接参数来切换旧任务的服务地址。

如进程异常退出前没有清理，可能留下旧托管进程；若端口被占用，新实例会拒绝启动，不会接管或杀死占用进程。可先人工关闭旧托管实例，或重启电脑后再重载。自动管理启动失败时插件仍可使用预览和其他已配置下载器，`backends`会显示错误；不可用后端的队列等待服务恢复，不会被调度为失败。

### 推荐：内置下载器表单

选择对应下载器后会显示这些字段：

| 下载器 | 用户主要填写 | 已预填 |
|---|---|---|
| qBittorrent（本机） | 用户名、密码 | Web UI 端口 8080、用户名 admin |
| aria2 手动连接 | RPC 密钥 | RPC 端口 6800 |

各下载器的独立目录通常留空，默认跟随同一个统一下载目录。想放到其他磁盘时，只需修改“统一下载目录”；想分别存放时再填写各下载器的可选独立目录。默认连接本机127.0.0.1，aria2的 `/jsonrpc` 路径已内置，无需手填URL。

升级时优先沿用旧版的全局默认下载器。旧配置只启用了一个下载器时会沿用它。旧群级选择由插件的统一选择取代。已有任务仍按原下载器和原路径管理。

### 高级：JSON（可选）

选择「高级 JSON」后，可配置远程机器、HTTPS、路径映射或多个连接。填写其中一个 `name` 作为当前下载器。只有一条有效配置时可留空。高级 JSON 支持 qBittorrent 和 aria2。

## 迅雷官方 CLI（Windows）

### 下载 CLI 并导入 AstrBot Skill

1. 在运行 AstrBot 的同一台 Windows 电脑上安装并登录[迅雷桌面客户端](https://pan.xunlei.com/download)。
2. 下载[迅雷官方 CLI Skill ZIP](https://down.sandai.net/xunlei-cli/xunlei-cli-skill.zip)，保留文件名 `xunlei-cli-skill.zip`。按下一步导入时直接上传这个 ZIP。
3. 打开 AstrBot WebUI 的 **插件 → 技能（Skills）**，点击右下角 **+ → 上传技能**，选中 ZIP 后点击「开始上传」，确认上传成功。见 [AstrBot 技能上传文档](https://docs.astrbot.app/use/skills.html#上传第一个-skill)。
4. 回到本插件的配置页面，将「下载器」选为 **迅雷官方 CLI**，CLI 路径留空，保存并重载插件。打开本插件的「目录设置」，确认识别到 `data/skills/xunlei-cli-skill/bin/windows-x64/xunlei-cli.exe`。上传包的文件名改过或自动识别失败时，可在这里浏览选择实际的 `xunlei-cli.exe`。也可以把同一个 ZIP 解压到自选目录，然后手动填写其中 `bin/windows-x64/xunlei-cli.exe` 的完整路径。

### 测试和使用

迅雷运行时，在「目录设置」点击「测试迅雷 CLI 连接」，或在群里由管理员执行 `/magnet test xunlei_cli`。测试只检查连接。群管理员执行 `/magnet on` 后，成员可执行 `/magnet add <磁力链接>`。命令末尾加 `--no-send` 可先验证下载并将文件保存在本机。插件确认迅雷未运行时会调用官方 CLI 启动它，并等待下载服务就绪后再提交任务。

**区分 Agent 权限和 Windows 权限：** `/magnet add` 和连接测试由插件直接运行 `xunlei-cli.exe`，可以保持 AstrBot「AI → 能力 → 使用电脑能力」为「不允许任何环境」。但运行 AstrBot 的 Windows 账号仍须能执行这个 EXE、连接正在运行的迅雷客户端，并写入下载目录。如果用自然语言让 AI 调用迅雷 Skill，则走 Agent 的执行工具，需要给相应角色配置本机执行权限才能调用本机的迅雷 CLI。参见 [AstrBot 技能文档](https://docs.astrbot.app/use/skills.html)。

迅雷报告完成且没有文件错误时，插件按任务目录里的实际文件和大小交付，支持迅雷只下载种子中的部分文件。取消时先核对任务归属并确认迅雷记录已移除，再清理插件的任务目录。

如果迅雷对同一磁力返回了早已存在、保存在其他目录的旧任务，请检查迅雷客户端的下载列表和「回收站 → 下载」。即使「下载中」和「已完成」均为 0，回收站里的记录仍可能触发迅雷去重。核对并移除对应旧记录后再提交。重试取消可清理插件自己的任务记录和目录，不会移除该迅雷任务或删除它的文件。

从迅雷微应用升级时，原下载器选择会迁移到迅雷官方 CLI。已有微应用任务请先用旧版插件处理，升级后也可在迅雷客户端手动管理。

### 高级 JSON 示例

下面是高级配置示例（路径仅为示例，请改为自己的专用目录）：

```json
[
  {
    "name": "qb",
    "kind": "qb",
    "enabled": true,
    "url": "http://127.0.0.1:8080",
    "username": "admin",
    "password": "填写自己的WebUI密码",
    "local_root": "D:/MagnetDownloads/qb"
  },
  {
    "name": "aria",
    "kind": "aria2",
    "enabled": true,
    "url": "http://127.0.0.1:6800/jsonrpc",
    "secret": "填写自己的RPC密钥",
    "local_root": "D:/MagnetDownloads/aria"
  }
]
```

- `name` 是群里选择时使用的名称，需唯一，使用小写字母、数字、下划线或连字符，以字母开头。
- `kind` 为 `qb` 或 `aria2`；`enabled:false` 会禁用该配置。
- `local_root` 是可选的独立目录，省略或留空时跟随统一下载目录；明确填写时优先保留，必须是绝对路径。插件在其下创建任务ID子目录。高级JSON显式目录不受可视化页面“关闭分别设置”影响；如需统一，请在JSON内清空或移除此字段。远程下载器仍需正确配置`remote_root`映射。
- 可选 `remote_root` 是下载器看到的同一共享目录。同机原生部署无需填写。它不是让远端文件自动复制到本机的功能。
- 「使用的高级配置名称」填写一个已启用的 `name`。
- 不要把密码或 RPC 密钥发进群里。WebUI 的敏感字段遮挡不等于磁盘加密。

### qBittorrent

启用 WebUI，设置用户名和密码，让 AstrBot 可访问 API。服务仅需在本机或受控内网监听。插件兼容 qBittorrent 5 的 stop 与旧版 pause API（旧版实际兼容性仍应在目标安装测试）。

任务使用独有标签和独立目录。插件在读取、停止或取消前核验归属；如果已有同哈希任务属于其他用途，会拒绝接管。不要在下载器里修改插件任务的标签、保存位置或文件选择。

### aria2

需要启用 RPC、DHT/BT，并设置 RPC secret。建议保存会话，重启时重新加载。例如 aria2 配置文件可包含：

```ini
enable-rpc=true
rpc-listen-all=false
rpc-secret=自行设置
enable-dht=true
bt-enable-lpd=false
seed-time=0
save-session=D:/MagnetDownloads/aria.session
save-session-interval=30
```

后续启动时按 aria2 的 `input-file` 选项加载已保存会话；文件首次不存在时不要盲目配置为必需输入。插件会处理磁力元数据任务切换到实际内容任务的 GID。RPC、DHT 可用不保证无种资源能下载。

## QQ 路径映射

新 ZIP 和分卷在任务使用的下载目录下的 `<任务完整编号>.archives/` 中生成。升级前已生成的 ZIP 仍在 AstrBot 的 `data/plugin_data/astrbot_plugin_magnet_delivery/archives/`。调用 `upload_group_file` 的文件路径必须也能被 **NapCat 进程**读取。

- 三者同机原生运行：一般无需配置额外映射。
- 如果 AstrBot 在容器中、NapCat 在宿主机，设置 `qq_local_prefix`（AstrBot 本机目录）和 `qq_remote_prefix`（NapCat 看到的同一目录）。两个字段必须同时填写。
- 如果下载器在另一台主机，必须自行挂载共享存储或部署受控传输。本版本不自动 SCP、HTTP 拉取远程文件。

## 群聊使用

下面示例使用默认唤醒前缀 `/`；若修改 AstrBot 的唤醒前缀，使用当前实际前缀。

```text
/magnet backends
/magnet preview magnet:?xt=urn:btih:实际资源哈希
/magnet preview 本群任务编号前8位
/magnet on
/magnet add magnet:?xt=urn:btih:实际资源哈希
/magnet tasks
/magnet status 任务编号前8位
/magnet cancel 任务编号前8位
/magnet tasks all
```

`on/off`、`auto` 需要管理员权限。群任务默认关闭，先执行 `on`。`allowed_groups` 非空时还需要匹配 WebUI 群号白名单。

发送 `/help` 会收到 AstrBot 内置帮助和磁力插件帮助。也可用 `/magnet-help` 或在 QQ 群里用 `/magnet help` 单独查看插件命令格式、用途和权限。

自动监听需额外执行 `/magnet auto on`，随后群内普通消息中的磁力会自动入队，每条消息最多处理3个链接。显式 add 指令不会被自动监听重复添加。发送 `/magnet auto off` 关闭自动监听，`/magnet off` 关闭本群新任务；已有任务继续运行。

`tasks` 显示当前群进行中、本机就绪及待处理异常，最多20项；`tasks all` 显示最近20条。`status` 可查本群历史任务。取消排队/下载/压缩任务时会删除下载文件、ZIP及临时文件，也可取消清理本机就绪或失败的任务。上传阶段不接受取消，因为不能保证已经发出的文件可撤回。

### 磁力预览

`preview_proxy` 默认跟随系统 HTTP(S) 代理。留空可直连，也可填写 HTTP(S) 代理 URL。它用于预览查询和截图，保存后重载插件。

使用 `/magnet preview <磁力链接或本群任务编号>`（也支持 `/磁力 预览 ...`）。不需要先执行下载开关 `on`，不会添加下载器任务，仍受 `allowed_groups` 白名单约束；任务编号只在当前群及机器人实例内解析。普通群成员可以预览本群别人提交的任务，不能查询其他群的任务编号。

信息来源为 [whatslink.info](https://whatslink.info/)，查询仅发送 BTIH 哈希，不发送群号、用户名、任务编号、tracker 或 passkey。群内结果保留来源链接。该服务返回的是第三方已有信息，不保证实时、完整或与实际内容一致；有些磁力没有截图，接口也不提供完整逐文件清单。本插件不会为预览偷偷启动 BT 下载。

文字结果中最多列出3个可用截图链接。默认尝试把 `whatslink.info` 及其子域名的截图以内联图片发送；若截图位于其他 CDN，只提供链接。管理员核对 CDN 后可在 `preview_image_hosts` 加入其域名（精确域名或点开头的子域后缀），不建议随意扩大范围。内联图片仅接受 HTTPS、指定域名、小于2 MiB的 JPEG/PNG/WebP，不跟随重定向；失败时保留文字和链接。

可配置 `preview_enabled`（全局开关）、`preview_inline_images`（内联图片开关）、`preview_cooldown`（每聊天默认15秒）、`preview_cache_seconds`（默认一小时）。成功结果按哈希最多缓存128项，重载后清空；未缓存的请求全局至少间隔3秒、一次只接受一个请求，429后至少暂停一分钟，不自动重试或轮换出口绕过额度。当前匿名 API 的实际配额由服务方决定，高额度申请有额外要求，不承诺私人机器人可获得授权。

上传报错或超时：先查看群文件，确认确实没有成功后再执行 `/magnet resend <任务编号>`。重发不重新下载或压缩。插件重启时发现上次处于上传阶段，也会标为未知，防止重复发送。

## 运行数据与恢复

数据库在插件数据目录，新 ZIP 在任务的下载目录。切换下载器后，已有任务继续使用提交时的下载器。若改了该下载器的地址或路径，请恢复原配置后再管理旧任务。凭据保存在插件配置中。

停止或清理失败不能当作“已取消并清理”。恢复下载器连接、目录权限或解除文件占用后，再执行cancel或点击管理页重试。取消操作只清理插件自己的任务目录，不扫描删除下载器中其他用途的文件。

如需手动清理遗留文件，请先在任务管理中确认相应任务已结束，并核对任务专用目录。

## 开发与扩展

- `main.py` 接入 AstrBot 指令、WebUI 和 OneBot 群文件接口。
- `core/manager.py` 调度任务并管理状态，`core/store.py` 保存任务和群设置。每个文件的上传确认和清理结果分别持久化，重载时可据此恢复。
- `core/backends.py`、`core/xunlei_cli.py` 负责下载器接口。`core/archiver.py`、`core/archive_worker.py` 负责压缩、验证与分卷，`core/cleanup.py` 限定清理范围。
- `views/` 是管理页面，`tests/` 是回归测试。用 `python build_release.py` 生成 AstrBot 安装 ZIP。

实现 `core.models.Backend` 的 `start / poll / stop / cancel / close`，通过 Snapshot 返回总大小、已下载、速度、完整文件列表及新远程任务 ID，再注册到 `core.backends.BACKENDS`。所有平台权限、聊天范围、持久化及压缩上传逻辑都留在公共层。将来接入 Transmission 等下载器时无需重写群聊逻辑。

## 验证

核心测试使用标准库 unittest、模拟 HTTP 响应和实际 ZIP 子进程；不需要真实磁力或账号：

```powershell
# 在插件目录的父目录运行
python -B -m unittest discover -s astrbot_plugin_magnet_delivery/tests -v
```

若需用真实 AstrBot 包核对命令，先把安装的 `backend/app` 加入 `PYTHONPATH`，并设置 `ASTRBOT_APP_PATH`，再运行相同命令。可用 `ARIA2_TEST_EXE`、`SEVENZIP_TEST_EXE` 指定实际程序来运行对应的集成测试。

真实部署验收仍需执行：小型公开测试磁力 → ZIP 可解压 → 原群文件可下载 → 取消实际下载 → 跨群访问拒绝 → 插件重载恢复。未配置真实服务时，不能把模拟测试当作真实下载/上传成功。
